# T028: Offline contract and CI release gate

The backend CI job uses the tested `personal-app/constraints-dev.txt` dependency
versions and runs on Python 3.11, 3.12 and 3.13. It explicitly removes the Helius
key for contract verification and tests. No CI step initiates live ingestion,
wallet history, signing, trading or deployment.

`scripts.verify_contracts` validates all eight checked-in JSON Schema documents
and both pinned IDLs, upgrades a temporary SQLite database with Alembic and checks
for schema drift. It replays the create, trade and pool fixtures twice through
`ReplayService`, which uses the application's journal, decoder, normalizers,
canonical event repository and lifecycle consumer. It validates actual provider
envelopes and Scout projections against their schemas and checks persisted row
counts for duplicate replay.

The three existing Scout goldens specify narrow stable projections. Their exact
field sets are listed in the runner, independently of expected JSON keys. No
fields are silently discarded based on the expected file. The pool contract's
`base_mint` is the normalized Scout mint. Mismatches fail with fixture names and
JSON paths without echoing field values. Funding, temporal uncertainty and the
full summary golden remain covered by the full pytest suite. The summary test
explicitly excludes only its generated run ID and local observation time.

Regression tests forbid network connections during the contract gate, verify
changed/missing/extra fields fail, and enable JSON Schema format checking for
nullable summary UUID references. The existing vault, ledger and JavaScript
verification jobs are retained.

This completes the T028 code and validation workflow without changing a public
contract or adding a provider mapping. Live provider authentication, long-running
intake and automatic finality scheduling still require operational verification.
